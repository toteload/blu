### Every executed SIR instruction records its type
- `inst_types` is the only place types are read from. `get_sref_type` reads it directly.
- `store_inst_comptime(ctx, f, idx, val)` stores a comptime value together with its type. These handlers now use it:
  - `SIR_return_type`
  - `SIR_get_decl_value` (both pointer cases)
  - `SIR_as` with no destination type
  - `SIR_type`, `SIR_unify`, `SIR_base_type`, `SIR_typeof`, `SIR_typeof_param`
- `SIR_func` gets its type (the function type) when its signature scope is finalized.
- `ref_typeof` was replaced by `expect_some_sref_type`. It reports a nil type as "Expected a value" instead of asserting. Every consumer that needs a typed operand uses it:
  - cast, `#len`, `#debug`, runtime load, index, negate, not
  - the arithmetic, bitwise and comparison operators

### Nil, never and unknown
The rules are in `notes/MEMORY.md`.
- New `VAL_NIL_NIL`: the zero-size value of type `nil`. Codegen uses it for every "no value":
  - empty blocks and declaration statements
  - a loop's exit `br` and `break` without a value
  - `if` without `else`
  - error placeholders

  `VAL_TYPE_NIL` now only means the type `nil`.
- `if` without `else` has type `nil` and discards the `then` value. This is decided. It is implemented in `gen_branch` in codegen: a given fallback replaces the branch's value. Before this change it took the `then` type, which caused an uninitialized read on the false path.
- Functions:
  - A function's return type is always a real type. `specializer_init_function` asserts it.
  - `SIR_return_type` and `SIR_ret` no longer have branches for a missing return type.
  - `SIR_ret` always coerces and emits `IIR_ret`.
- Block types:
  - A block's type is the unification of its breaks, starting from `never`. A block with no breaks has type `never`.
  - `eval_unify` treats `never` as unifying with any type.
- `#debug` on `nil` or `never` prints only the type, not an address.

## Left to do

### Next step: how IIR represents "no value" (step 3)
Present the IR format for review before implementing.
- Codegen no longer produces a nil `br` or `ret` operand. As a result:
  - `IIR_br_void` and `IIR_ret_void` are never emitted.
  - The `iref_is_nil(ref)` branch in the specializer's runtime `SIR_br` is dead code.
  - So is the interpreter's `layout_of` special case for type 0.
- Options:
  - (a) Keep `br_void`/`ret_void`, and select them when the operand's type is `nil`.
  - (b) Drop them and use `br`/`ret` with the zero-size `VAL_NIL_NIL`.
- `notes/iir_plan.md` currently says the void opcodes exist so that IIR refs are never nil. Update it to match whichever option is chosen.

### Finish the `inst_types` invariant, then drop `expect_some_sref_type`
Some executed instructions still record no type. Today `expect_some_sref_type` turns them into "Expected a value"; these are its only remaining sources:
- `SIR_repeat` (`continue`) should record `never`.
- `SIR_br` should record `never`. Today `inst_types[br]` holds the type of the value it carries, and `finalize_residual_block` relies on that. It should read the type of `SIrBr.value` instead.
- An assignment returns its `SIR_store` as the expression value. Codegen should return `VAL_NIL_NIL` instead, like declaration statements.

After that, `expect_some_sref_type` can become `get_sref_type` plus an `Assert`. Optionally, let `never` coerce to any type, so that `cast(i32) continue` is accepted as unreachable code.
